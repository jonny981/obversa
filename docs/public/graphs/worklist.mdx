---
title: "Worklist"
description: "Run a fixed item list through a fixed stage sequence."
---

`boundedItem` is a pure graph form for a declared item list and a linear stage
sequence. A run-start record freezes the item order.

The form returns one batch within the global and per-stage limits. It waits
for every recorded attempt in that batch before it returns another batch.

## Run the example

From an Obversa checkout, run:

```bash
pnpm example:worklist
```

The example sends two documents through two stages and one aggregate node. It
prints this JSON report:

```json
{"decision":{"kind":"complete","output":{"items":{"doc-1":"done","doc-2":"done"},"aggregate":{"passed":2}}},"events":11,"planDigest":"sha256:0eda540c17f5161115076aad8952b0e2e81f421688f35d6c6f8904c158e08c81","bounds":{"dispatches":{"min":{"kind":"known","value":3},"max":{"kind":"known","value":5}},"maxConcurrency":{"kind":"known","value":2},"maxFanOut":{"kind":"known","value":2}}}
```

The clean-consumer check compiles and runs the same source from the packed
package with TypeScript 6 and TypeScript 7. Its source is
`examples/packages/worklist.ts`.

## Define a worklist

```ts
import {
  boundedItem,
  compileGraph,
  type BoundedItemDefinition,
} from '@obversa/runtime';

const definition: BoundedItemDefinition = {
  id: 'document-checks',
  definitionVersion: 1,
  data: {
    items: ['doc-1', 'doc-2'],
    globalConcurrency: 2,
    perStageConcurrency: 2,
    attemptCapPerStage: 1,
    failurePolicy: 'fail',
    aggregate: 'tally',
  },
  nodes: [
    { id: 'summarize', data: {} },
    { id: 'verify', data: {} },
    { id: 'tally', data: {} },
  ],
  edges: [
    { id: 'summarize-to-verify', source: 'summarize', target: 'verify', data: {} },
  ],
};

const graph = compileGraph(boundedItem, definition);
```

## Recorded behaviour

- **Frozen items:** `items-frozen` must match the declared item order. A later
  freeze record does not add items.
- **Stage attempts:** Claims, completions, failures, pauses, and resumes update
  one item and stage.
- **Retries:** Each retry uses a new attempt position. A reopen keeps completed
  neighbours untouched and resets the selected item's cap count.
- **Aggregate:** The optional aggregate runs after every item settles.

The graph executor does not create worklist records. A host must record the
`BoundedItemEvent` values that the form folds.

## Limits and output

The all-pass example has five dispatches: four stage attempts and one
aggregate attempt. Its maximum concurrency and batch size are two.

The complete output maps each item to its last status and includes the
aggregate result.
