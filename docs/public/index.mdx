Model how your team really works: named roles, reviews that send work back, and a record in plain files.

You describe how work should move from a request to a checked result: the
steps, who does each one, the reviews, and where a person decides. Obversa
runs that workflow one bounded engine call at a time and records every step.

Agents are not deterministic, so nothing guarantees that every step of a
process is followed, in the right order, under the right conditions.
Obversa puts a deterministic process around the inference: many small jobs,
each with a review cycle. A workflow built into a frontier harness cannot
be saved, shared or repeated; an Obversa workflow is a file you save, share
and run again. And it models process at every layer, the organisation, the
team and the individual.

## Inference at the leaves

Inference belongs mostly at the leaves. Around each inference step you can
build as much process as you like: deterministic scripts, tools and checks,
so that the job an agent has to do is clearer, simpler, better bounded and
cheaper. Squeeze the determinism out of the agents and what is left is a
set of very specific, focused agents doing narrow tasks.

That improves quality, and it does something else: a narrow, well-bounded
task can be done by a small open-weight model tuned to it, as well as a
frontier model would, at a fraction of the cost.

Process engineers call the method value stream mapping: understand the
process, then make the steps that add no value cheaper, faster, or cut
them out. The same idea applies here. Lift every deterministic step out of
the agents, so their context shrinks to the parts that truly need
inference.

## See a team run

Eleven named steps model the work as a real team ships a feature: the team
records context and requirements, writes and reviews a plan, writes and
reviews tests, implements and verifies the change, then records approval and
evidence. The file is complete; copy it, put your brief in, run it with Node.

```ts
import { ClaudeCliEngine } from '@obversa/engine-claude-cli';
import { CodexEngine } from '@obversa/engine-codex';
import { run } from '@obversa/runtime';
import { featureDelivery } from '@obversa/teams';

const workspace = process.cwd();
const analyse = {
  engine: new ClaudeCliEngine({ defaultModel: 'claude-sonnet-4-5', permissionMode: 'bypassPermissions' }),
  identity: {
    adapter: 'claude-cli', provider: 'anthropic', modelFamily: 'claude', model: 'claude-sonnet-4-5',
  },
};
const implement = {
  engine: new CodexEngine({ defaultModel: 'gpt-5.6-luna', permissionMode: 'bypassPermissions' }),
  identity: {
    adapter: 'codex', provider: 'openai', modelFamily: 'gpt', model: 'gpt-5.6-luna',
  },
};
const reviewer = {
  engine: new ClaudeCliEngine({ defaultModel: 'claude-sonnet-4-5', permissionMode: 'bypassPermissions' }),
  identity: {
    adapter: 'claude-cli', provider: 'anthropic', modelFamily: 'claude', model: 'claude-sonnet-4-5',
  },
};
const approve = {
  engine: new ClaudeCliEngine({ defaultModel: 'claude-sonnet-4-5', permissionMode: 'bypassPermissions' }),
  identity: {
    adapter: 'claude-cli', provider: 'anthropic', modelFamily: 'claude', model: 'claude-sonnet-4-5',
  },
};

const team = featureDelivery({
  brief: 'Deliver a pure triple(value) function in src/triple.mjs with a Node test in test/triple.test.mjs.',
  workspace,
  files: ['src/triple.mjs', 'test/triple.test.mjs'],
  testFiles: ['test/triple.test.mjs'],
  test: { command: 'node', args: ['--test', 'test/triple.test.mjs'] },
  analyse,
  implement,
  reviewers: [{ name: 'correctness', seat: reviewer, scope: 'implementation' }],
  reviewThreshold: 1,
  approve,
  maxKickbacks: { plan: 3, 'tests-first': 3, implement: 3 },
});

const result = await run(team, { cwd: workspace });
console.log(JSON.stringify(result.outcome, null, 2));
if (result.outcome.status !== 'pass') process.exitCode = 1;
```

A writing seat can write anywhere the process can: the file starts its
Claude and Codex seats with permission prompts off, which is what lets a
model write files. Run it in a directory you are willing to let a model
change.

Write many small jobs, each with its own review, for the specific research,
implementation and test tasks in your process, rather than a few large
ones. A coarse step hands the whole task to one inference and hopes. A
small step with a review cycle is a process the run can hold to, and the
team above is the shape to grow, not the size to stop at.

The result of a successful run includes all eleven named stages:

```json
{
  "status": "pass",
  "summary": "dag \"feature-delivery\": all 11 node(s) green"
}
```

Every step's own words are in that record: what the research seats found,
what the implementer wrote, the test command's exit, the reviewers' reasons,
and the approval. The files the models wrote, the notes and the approval
included, are on the [feature delivery](/workflows/feature-team) page, and
[the examples](/workflows) have the two smaller teams and the single
mechanisms they are built from.

## What you can do with it

- **Run a ready-made team on your own files.** A writer and a reviewer, a
  review panel with a threshold, or feature delivery from brief to approval:
  one import, your brief, your engines, run.
  [The teams package](/packages/teams).
- **Give work a shape in one call.** Steps in order, a graph with parallel
  branches, a loop that revises until it passes, a tournament of
  candidates, a quorum of opinions. [Workflows](/concepts/workflows).
- **Say what each step does and what done means.** A sentence for each on
  the node, and the reviewer judges against it.
  [Workflows](/concepts/workflows).
- **Send work back to the step that owns it.** A failed review names the
  step that must fix it, and the work goes back there with the findings.
  [A review that sends work back](/reviewing/review-loop).
- **Get a second opinion that is really a second opinion.** The implementer
  and every reviewer run on different model families, checked before a run.
  [The teams package](/packages/teams).
- **Stop for a person.** A callback gate puts one decision in front of
  someone and the run carries on from that step with the answer.
  [Callback gates](/reviewing/callback-gates).
- **Approve only what was proved.** An approval is bound to the exact bytes
  and test result it was given. [Proof acceptance](/reviewing/proof-acceptance).
- **Run a step as a command.** The step passes on the exit code, never on a
  model's report. [Workflows](/concepts/workflows).
- **Use the engines you have.** Claude, Codex, Grok, OpenCode, the Agent
  SDK, the Anthropic API, or one you write to the contract.
  [Engines](/packages/engine).
- **Define agents and skills in markdown.** The files your team already
  writes become the persona and the skills a step runs with.
  [Workflows](/concepts/workflows).
- **Give each step its own worktree.** A change touches only the paths it
  declared, and a mismatch pauses the run.
  [The workspace contract](/workspace/contract).
- **Keep every step in a file on disk.** Events and artifacts beside each
  other, no server and no database.
  [How a run is recorded](/recording/how-a-run-is-recorded).
- **Kill a run and start it again where it stopped.** Nothing finished is
  done twice. [The runner](/packages/runner).
- **Give the team a memory.** In process or in private git refs, curated
  and grounded by the steps themselves. [Memory](/memory).
- **Put a diff in front of a person in their own editor.** Or drive runs
  from cmux. [Surfaces](/concepts/surfaces).
- **Let team members talk.** Messages, mentions, and a teammate woken by
  name, in rooms that are files.
  [A team conversation](/workflows/team-conversation).
- **Set a budget and read the cost.** A cap on an attempt and a cost report
  for the run. [The runtime](/concepts/runtime).


## Packages

| Package | Purpose | Version |
| --- | --- | --- |
| `@obversa/runtime` | Compiles and runs pipeline, review-loop, and DAG graph forms | `1.0.0` |
| `@obversa/runner` | Supervises stored graph runs in bounded workers | `0.1.0` |
| `@obversa/engine` | Defines the contract for one bounded engine attempt | `0.1.0` |
| `@obversa/process` | Runs one child process with a deadline and a readable result | `0.1.0` |
| `@obversa/memory` | Defines the memory command contract | `0.1.0` |
| `@obversa/memory-simple` | Stores memory in one process | `0.1.0` |
| `@obversa/memory-git` | Stores memory in private Git references | `0.1.0` |
| `@obversa/teams` | Three teams of models you run on your own work | `0.1.0` |
| `@obversa/surfacer` | Runs one local surface session | `0.1.0` |
| `@obversa/source` | Opens a git diff for inline review | `0.1.0` |
| `@obversa/engine-agent-sdk` | Runs one engine attempt through the Agent SDK | `0.1.0` |
| `@obversa/engine-anthropic-api` | Runs one engine attempt through the Anthropic API | `0.1.0` |
| `@obversa/engine-claude-cli` | Runs one engine attempt through the Claude CLI | `0.1.0` |
| `@obversa/engine-codex` | Runs one engine attempt through the Codex CLI | `0.1.0` |
| `@obversa/engine-grok-cli` | Runs one engine attempt through the Grok CLI | `0.1.0` |
| `@obversa/engine-opencode-cli` | Runs one engine attempt through the OpenCode CLI | `0.1.0` |

The six engine plugins and the two memory adapters have their own pages in
the Packages group. The runtime version matches the repository release tag.
Other packages keep their own manifest versions.

The packages have one dependency direction. The runtime imports the memory port.
Each memory adapter also imports the memory port. The runtime does not import a
memory adapter.
