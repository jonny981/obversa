Copy a complete team, put your brief and your coding agents in, and run it.
Each example is a TypeScript file under `examples/` in the repository, with
its brief and sample inputs beside it, and each page shows what one real
run printed. For one mechanism on its own, read [Patterns](/patterns/writer-and-reviewer).

## Run one

1. Set the project up as [Installation](/get-started/installation)
   describes.
2. Copy the file and the folder beside it, its brief and sample inputs,
   into the directory the work belongs in.
3. Sign in to the coding agents the file names, Claude Code and Codex in
   most of them.
4. Run it with `npx tsx <file>.ts`.

Each file reads its brief and inputs relative to the directory you run it
in, so keep the layout the repository uses:

```text examples/
examples/
  feature-team.ts
  forge-helper.ts
  teams/
    feature-delivery.ts
    briefs/triple.md
  use-cases/
    engineering/
      backlog-groom-then-rank.ts
      briefs/backlog.md
      backlog/raw.md
    business/
      contract-playbook.ts
      briefs/playbook.md
      contracts/msa.md
    other/
      translate-reflect.ts
      briefs/translation.md
      glossary/en-fr.md
      source/article.md
```

The offline feature team runs with no model at all. Start there to see the
shape before you spend a token.

## Software delivery

- **[Feature team, offline](/workflows/feature-team-offline).** Five stages
  and a panel of three, every job a small function. The shape with nothing
  else on show.
- **[Feature delivery](/workflows/feature-team).** Nine stages from a brief
  to a person's decision: research with its own reviews, a plan, tests
  before code, and an implementation held to green tests and a panel.
- **[Shipping through GitHub](/workflows/forge-helper).** After the review
  passes: push the branch, open one pull request, pass a strict gate on the
  exact head revision, squash the merge.
- **[Backlog grooming](/workflows/backlog-groom-then-rank).** Raw tickets
  become stories with acceptance checks, a second model reads them back,
  and the product owner ranks.

## Business

- **[Contract review](/workflows/contract-playbook).** Every clause mapped to
  the playbook rule it meets or breaks, redlines in the playbook's wording,
  and a lawyer decides what is sent.

## Other fields

- **[Translate and reflect](/workflows/translate-reflect).** An article
  translated against a glossary, read back by an editor on another model,
  and a person decides the nuance.

## Markets

- **[Market session advice](/workflows/markets/market-session-advice).** A session host reads recorded observations, a typed assessment routes each, an uncertain one is researched, and a person is asked where action would be considered.

## Sales

- **[Draft, then send](/workflows/sales/draft-then-send).** A model drafts one note per warm contact, a person decides on each, and the record keeps what was sent, what was refused and why, and what is still waiting.

## Support

- **[Triage with escalation](/workflows/support/triage-with-escalation).** A typed classification routes each ticket, every ticket gets a drafted reply, the routine ones are answered, and the rest stop on a question for a person with the draft beside them.

## Research

- **[Literature watch](/workflows/research/literature-watch).** A model summarises the supplied papers, a person decides which summaries enter the lab's memory, and a question is answered from the kept notes alone.

## Finance

- **[Invoice chase](/workflows/finance/invoice-chase).** A command reads the ledger, a model drafts a chaser per overdue invoice, the mailer sends the plain ones, and a disputed one stops on a question for a person with the draft beside it.

## Editorial

- **[Writer, grader, cap](/workflows/editorial/writer-grader-cap).** One model drafts a post, a grader from another family returns findings against the house style, the writer runs again up to a limit, and an editor decides whether it is published.

## Hiring

- **[Shortlist](/workflows/hiring/shortlist).** A script applies the filters and records each exclusion's rule, two rankers from different model families rank the rest against the brief, a judge lands the better ranking, and a person decides who is shortlisted.

## Knowledge

- **[Vault curator](/workflows/knowledge/vault-curator).** A model proposes where each inbox note belongs and a cleaned version, a person decides what is filed and where, and a question is answered by searching the vault and citing the passages.

## Ops

- **[Approve the payload](/workflows/ops/approve-the-exact-payload).** A person's yes is recorded against the digest of the request's bytes; the same bytes are sent, and a payload that differs by one field asks again.
- **[Handoff that resumes](/workflows/ops/handoff-that-resumes).** A run stops after its first stage, the next worker is given only the record, and it carries on from the exact state; the finished stage never runs again.

## Product

- **[Shape Up cycle](/workflows/product/shape-up-cycle).** One cycle composed of workflows: requests shaped into pitches, a betting table of three seats each checked by Jev, a person's bets, a build inside the appetite, and a cool-down, with the hill read from the record.
