Install Obversa, write one file, and a team of models writes code, runs
your tests and reviews the result before you see it. Each team below is a
complete file: copy it, put your brief and your engines in, run it.

The smallest team, whole. A Claude seat writes the files the brief names,
Node runs the test, and a Codex seat reviews the result:

```ts
import { claude } from '@obversa/engine-claude-cli';
import { codex } from '@obversa/engine-codex-cli';
import { run } from '@obversa/runtime';
import { briefFromFile, stage, workflow, type TeamSeat } from '@obversa/runtime';

interface WriterReviewerEngines {
  readonly claude: (model: string) => TeamSeat;
  readonly codex: (model: string) => TeamSeat;
}

const realEngines: WriterReviewerEngines = { claude, codex };

function createWriterReviewerPair(engines: WriterReviewerEngines = realEngines) {
  return workflow('writer-reviewer-pair', {
    brief: briefFromFile('briefs/add.md'),
    options: { timeout: '10m' },

    roles: {
      write: engines.claude('claude-sonnet-4-5'),
      review: [engines.codex('gpt-5.6-luna')],
    },

    stages: [
      stage('write', {
        agent: 'write',
        writes: ['src/add.mjs', 'test/add.test.mjs'],
        desc: 'Write the function and its test from the brief.',
        gate: 'The files named in the brief exist in the workspace.',
        retry: 1,
      }),
      stage('test', {
        run: ['node', '--test', 'test/add.test.mjs'],
        desc: 'Run the test command against the written files.',
        gate: 'The test command exits 0.',
        sendsBackTo: 'write',
      }),
      stage('review', {
        panel: 'review',
        agree: 1,
        desc: 'Read the code, the test and its result.',
        gate: 'The change meets the brief.',
        sendsBackTo: 'write',
      }),
    ],
  });
}

const result = await run(createWriterReviewerPair());
console.log(JSON.stringify(result.outcome, null, 2));
```

and the files the writer left.

## Teams you run on your own work

- [A writer and a reviewer](/workflows/writer-and-reviewer). One model
  writes, your test runs, and a model from another family reviews.
- [A review panel with a threshold](/workflows/review-panel). Several
  reviewers from different model families, and the change passes when
  enough of them accept.
- [Feature delivery](/workflows/feature-team). Nine stages from a brief to
  a person's decision. Tests come before code, and work goes back to the
  stage that owns it.

Each team is a graph of named steps. Every step carries a `desc` sentence
saying what it does and a `gate` sentence saying what must be true for it
to count. Both go into the run record, and a writing seat reads them in its
prompt.

## Teams outside a software change

The same form, for the work most teams do that isn't a pull request. Each
file stops at a person, so nothing is sent or filed without one. Each is a
complete file, with its brief and sample inputs beside it under
`examples/use-cases/`.

Each page carries one real run. Two reached their person. The third stopped
earlier, when its reviewer sent the work back a third time and the loop ran
out of attempts instead of passing stories nobody had agreed.

Software and product engineering:

- [Backlog grooming, then a person ranks](/workflows/backlog-groom-then-rank).
  Raw tickets become stories a second model checks, and the product owner
  ranks them.

Business and commercial:

- [A contract against a playbook](/workflows/contract-playbook). Each
  clause checked against a playbook, with redlines and a negotiating note,
  and a lawyer decides what goes back.

Other:

- [Translate, then reflect on the translation](/workflows/translate-reflect).
  An article translated into French against a glossary, with a table of
  the terms where the two pulled apart. A person decides whether to publish.

## Mechanisms shown one at a time

All but one of these files run offline, with no model.

- [Three candidates, one winner](/workflows/tournament). Three isolated
  attempts at one task, a judge that scores them, and only the winner
  lands.
- [A command decides the path](/workflows/command-kickback). A test
  command sends a red run back to the writer, and another command's exit
  code picks which review runs.
- [A person decides](/workflows/approval). A yes-or-no question to a
  person as a step. A no sends the work back with the person's note, and
  an unanswered question pauses the run.
- [A review that sends work back](/workflows/offline-review). A reviewer
  rejects the first draft with a reason, and the second draft passes.
- [A file change approved byte for byte](/workflows/safe-change). Exact
  output bytes are approved, each target is backed up before a merge, and
  a mismatch pauses the run.
- [A feature from written issue to approval](/workflows/feature-delivery).
  One issue through analysis, implementation, a test run, a review panel
  and a person's approval. Claude and Codex seats do the model work.
- [Shipping a reviewed change through GitHub](/workflows/forge-helper).
  One pull request, a strict gate on the exact head revision, and a squash
  merge.
