---
title: "A writer and a reviewer"
description: "One model writes the files your brief names, your test command runs, and a model from a different family reviews the result."
---

Give one model a brief and another model the job of checking it. This
file names two roles and three stages: a Claude seat writes a function and
its test, Node runs the test, and a Codex seat reviews the files once the
test passes. A red test or a rejection sends the work back to the writer,
which runs again with the findings, once.

```bash
npm install @obversa/obversa
```

Set up the project as [Installation](/get-started/installation) describes.

## The file

The brief is `briefs/add.md` beside the file. Its body is the task, and
its front matter names the files the brief expects written. Change those to
your own and run the file from the directory the work belongs in. Paths in
the file, the test command's among them, are relative to that directory.

```ts
import { claude } from '@obversa/engine-claude-cli';
import { codex } from '@obversa/engine-codex-cli';
import { run } from '@obversa/runtime';
import { briefFromFile, stage, workflow, type TeamSeat } from '@obversa/runtime';

interface WriterReviewerEngines {
  readonly claude: (model: string) => TeamSeat;
  readonly codex: (model: string) => TeamSeat;
}

const realEngines: WriterReviewerEngines = { claude, codex };

function createWriterReviewerPair(engines: WriterReviewerEngines = realEngines) {
  return workflow('writer-reviewer-pair', {
    brief: briefFromFile('briefs/add.md'),
    options: { timeout: '10m' },

    roles: {
      write: engines.claude('claude-sonnet-4-5'),
      review: [engines.codex('gpt-5.6-luna')],
    },

    stages: [
      stage('write', {
        agent: 'write',
        writes: ['src/add.mjs', 'test/add.test.mjs'],
        desc: 'Write the function and its test from the brief.',
        gate: 'The files named in the brief exist in the workspace.',
        retry: 1,
      }),
      stage('test', {
        run: ['node', '--test', 'test/add.test.mjs'],
        desc: 'Run the test command against the written files.',
        gate: 'The test command exits 0.',
        sendsBackTo: 'write',
      }),
      stage('review', {
        panel: 'review',
        agree: 1,
        desc: 'Read the code, the test and its result.',
        gate: 'The change meets the brief.',
        sendsBackTo: 'write',
      }),
    ],
  });
}

const result = await run(createWriterReviewerPair());
console.log(JSON.stringify(result.outcome, null, 2));
```

<Warning>
Run the file in a directory you're happy for a model to change. The Claude
seat runs with permission prompts off, so it can run any command the process
can.
</Warning>

Each seat comes from its plugin: `claude('claude-sonnet-4-5')` and
`codex('gpt-5.6-luna')` carry the identity the plugin records, and the
record and the family check read it. The Codex seat runs sandboxed to the
workspace with approvals off. Each helper takes an options object to choose
otherwise.

```js
  assert.strictEqual(add(2, 3), 5);
});

  assert.strictEqual(add(-1, 1), 0);

});
```

## The team's shape

| stage | does | done when |
| --- | --- | --- |
| write | Write the function and its test from the brief. | The files named in the brief exist in the workspace. |
| test | Run the test command against the written files. | The test command exits 0. |
| review | Read the code, the test and its result. | The change meets the brief. |

The reviewer runs only after the test passes. A red test or a rejection is
a revision request aimed at `write`. The `retry` on that stage (one here)
bounds how many times the pair goes round.

The writer and the reviewer must come from different model families. The
team refuses to run when they share one, so one model can't approve its own
work.

`writes` names the files the write stage produces. A missing or empty one
fails the stage by name, and so does a change to another declared file.
Files the workflow doesn't declare aren't checked.
