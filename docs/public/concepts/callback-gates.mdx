---
title: "Callback gates"
description: "A callback gate stops the line until an answerer supplies one structured result. The answerer can be a person, an agent, or a remote service."
---

A callback gate is a point in a graph where the runtime stops and waits. The
runtime resumes when one structured result arrives.

The gate is a contract, not a user interface. The runtime does not know or
select the answerer.

## The flow

1. The runtime records a durable `CallbackRequested` event.
2. A router sees the pending request and claims it. The claim is atomic. One
   router holds one request.
3. The router collects one structured response from its answerer.
4. The router submits the response through a separate command.
5. The runtime records the response and resumes the run.

Gate state lives in durable events. If a router fails, the request stays. A
lost callback does not lose the gate.

## Answerers

A gate does not care who answers. Answerer types include:

- **A person.** A router opens a surface in your terminal host. You decide,
  and the surface returns your decision as structured data.
- **An agent.** An interactive agent examines the request and answers it.
- **A remote service.** A service receives the request and calls back with
  the result.
- **An external system.** Any system that can submit the response command.

A gate can declare its expected answerer type as a hint. A host can then show
"needs you" for a person. The hint does not change the contract.

## Delivery channels

Version 1 delivers callbacks locally. The contract also permits remote
delivery: a gate that waits can expose a callback address over HTTP. Delivery
is a channel, not a new gate type.

A callback address authenticates its caller. It binds to one gate instance.
A replay against a closed gate has no effect.

## Why gates are structured

A gate response is data with a schema, not free text. Structured responses
give you three properties:

- The line can branch on the response without interpretation.
- The response binds to the exact evidence that the answerer saw.
- The record of the decision stays readable after months.

The request digest covers the decision text, response schema, and referenced
input bytes. A change to those values makes an earlier response stale. A
change to pane placement, layout, theme, or visual style does not.
