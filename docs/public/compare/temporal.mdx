Pick Temporal when a process must survive anything for days on a service;
pick Obversa when the work is a team of coding tools on one machine and
the process between them should be written down. Temporal, in its own
words, is "a scalable and reliable runtime for durable function executions
called Temporal Workflow Executions." A workflow calls activities, every step is an event in
a history, and after a crash a new worker replays the history and continues
from the exact point. Obversa is a TypeScript library for a team of coding
agents on one machine: named roles, a review that runs a step again, a
person at the gate, and a record on disk that a stopped run carries on from
without repeating a finished step.

## What each is for

| The job | Temporal | Obversa |
| --- | --- | --- |
| Unit of work | A workflow calling activities. | A stage: an engine call, a command, a panel or a person, with the files it may write. |
| The workers | Your code in activities, which may call any model. | Engines such as Claude Code, Codex, Grok and OpenCode, a fresh process per call, or an API engine. |
| A review that fails a step | Control flow you write in the workflow. | Built in: the findings go to the stage that owns the fix, which runs again, up to a limit you set. |
| A person deciding | A signal the workflow waits for. | A person role. The run pauses on the question, and the answer arrives through the callbacks client. |
| More than one provider | Inside your activities, with a client library. | Each role names its engine. A review seat from another provider is one line. |
| A run that survives a crash | Event history and replay on a service; the run continues from the exact point. | A run records to a file and carries on from it with `resume: true`; the supervised runner restarts a killed run from its own record. Finished steps never run twice. |
| Where it runs | A service you run or rent, plus your workers. | A library, no server. |
| Languages | SDKs in several languages, TypeScript among them. | TypeScript. |

## Where each wins

- **Temporal, when durable execution is the requirement**: multi-day runs,
  many workers, replay after any failure, across machines.
- **Temporal, when you already run it** for other work, or need a language
  other than TypeScript.
- **Obversa, when there's one machine**, the agents are tools on it, and a
  server would be more than the job needs.
- **Obversa, when the review and the person should be declared**, not
  written as control flow each time.
- **Obversa, when the team is a file you can read** with the record beside
  it.

## Together

An Obversa run is a program with an exit code, so a Temporal activity can
start one and wait for it, and an Obversa stage can run any program as a
command:

```ts examples/teams/writer-reviewer-pair.ts (excerpt) {2}
      stage('test', {
        run: ['node', '--test', 'test/add.test.mjs'],
        desc: 'Run the test command against the written files.',
        gate: 'The test command exits 0.',
        sendsBackTo: 'write',
      }),
```

Keep the days-long, many-worker process in Temporal, and let one activity
run the coding team as an Obversa file with its own record.
