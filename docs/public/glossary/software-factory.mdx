Run a workflow, and you have what the phrase promises. People who say
software factory mean a ticket that ends in a merge a person still has to
approve, with agents doing the work between. What runs is a process: one
agent writes, another reviews, the writer runs again when the review fails,
tests run as commands, and a person decides at the end. The smallest version of that shape is the
neighbour term, [an agent pipeline with a review and a person](/glossary/agent-pipeline).

## In Obversa

The process is one file. Named roles, one engine each, from more than one
provider, and a person for the last word:

```ts examples/teams/feature-delivery.ts (excerpt)
const writer = claude('claude-sonnet-4-5');
const implementer = codex('gpt-5.6-luna');
const secondReviewer = opencode('opencode/big-pickle', { executable: resolveCommandExecutable('opencode') });
```

Seven steps follow, from a ticket to a change a person is asked to ship: a
cheap model types the ticket, a plan is reviewed by another model family,
two seats implement in their own worktrees and the tests pick the winner,
a test command and a review panel hold the code to green with a judge
saying when another round stops being worth it, and the person approves
the exact bytes. The whole file and what a run of it did are on
[Feature delivery](/workflows/feature-team), and
[Shipping through GitHub](/workflows/forge-helper) is the step after the
person says yes: push, one pull request, a strict gate, a squash merge.

## What people want

| What you want | What you write |
| --- | --- |
| A ticket that ends in a merge. | A workflow whose first stage reads the issue and whose last stage is a person at the merge. |
| Many agents on one change. | Named roles, one engine each, from more than one provider. |
| Quality without a human reading every diff. | A review role that fails a stage with findings, and commands for the tests. |
| Runs that don't lose work. | A record of every step as it happens. A workflow started again with `resume: true` carries on from that record, and the [supervised runner](/driving/runner) restarts a killed run from its own record. |
| A place to watch it. | Every run can [serve its own page](/driving/monitor). |

A review that can fail a stage is what makes the review count. A pipeline
that never runs a step again is a queue. A product factory is the same
picture with a larger scope, and the file has the same shape.
