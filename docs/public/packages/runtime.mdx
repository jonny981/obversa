`@obversa/runtime` is the package you install to run a workflow. You write
the workflow as TypeScript, hand it the engines and storage you chose, and
call it. It runs the steps one bounded engine call at a time and appends
every step to a record on disk.

```bash
npm install @obversa/runtime
```

Node.js 22.12 or later. Nothing else to install: no database, no service to
keep running. A run can serve its own page while it works; see
[watch a run in the browser](/driving/monitor).

## Two ways in

**Write a workflow and run it.** The job API is the everyday one: name the
steps, say what each needs, put a review where it belongs, and call `run`.
`dag` is the general shape (nodes keyed by name, each with `needs` as one
name or a list, an optional `desc` saying what it does, an optional `gate`
saying what done means, an optional `when`, and a `job`; `desc` and `gate`
reach the plan, the record and the node reviewer's input); `pipeline` is its
shorthand for steps that go in one direction; `loop`, `sequence` and
`parallel` are the other shorthands. Reviews go in with `reviewPanel`,
`tournament`, `quorum` and `kickback`. A person's decision goes in with a
callback gate.

**Compile a graph and drive it yourself.** Under the job API sits the
graph contract: `compileGraph` with a graph form (`dagGraphType` is the
built-in one), `createGraphExecutor` to run it against stored events, and
`resolveGraphPlan` to see exactly what will run. This is the layer a host
uses to supervise, pause and resume runs, and the layer you build on to
write a workflow shape of your own.

## See it run

The smallest example stores a three-stage pipeline and drives it through
the graph executor. It runs offline.


```ts
import { mkdtemp, realpath, rm } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { join } from 'node:path';

import {
  compileGraph,
  createGraphExecutor,
  dagGraphType,
  persistRunDefinition,
  resolveGraphPlan,
  type DagDefinition,
  type GraphNodeBinding,
  type PlanResolution,
  type RunStoragePolicy,
} from '@obversa/runtime';
import { defineGraphDefinition } from '@obversa/runtime/testing';
import { createLocalRunStorage } from '@obversa/runtime/storage/local';

const definition: DagDefinition = defineGraphDefinition({
  id: 'release-pipeline',
  definitionVersion: 1,
  data: {
    globalConcurrency: 1,
    keyedConcurrency: {},
    stopOnError: true,
    retryCapPerNode: 0,
  },
  nodes: [
    { id: 'draft', data: { kind: 'required', key: null } },
    { id: 'review', data: { kind: 'required', key: null } },
    { id: 'publish', data: { kind: 'required', key: null } },
  ],
  edges: [
    { id: 'draft-to-review', source: 'draft', target: 'review', data: {} },
    { id: 'review-to-publish', source: 'review', target: 'publish', data: {} },
  ],
});

const packageIdentity = {
  source: 'npm:@example/release-pipeline',
  version: '1.0.0',
  digest: 'sha256:3333333333333333333333333333333333333333333333333333333333333333',
} as const;
const resolution: PlanResolution = {
  package: packageIdentity,
  admission: { package: packageIdentity, permissions: [] },
  executionLanes: [],
};
const graph = compileGraph(dagGraphType, definition);
const plan = resolveGraphPlan(graph.describe(), resolution);

const storagePolicy = {
  schemaVersion: 1,
  maxEventPayloadBytes: 64_000,
  maxAppendBatchBytes: 128_000,
  maxArtifactBytes: 1_000_000,
  maxTotalArtifactBytesPerRun: 4_000_000,
  retention: 'until-run-delete',
  sensitiveContent: {
    marked: 'reject',
    exact: 'reject',
    freeText: 'redact-before-hash',
  },
} as const satisfies RunStoragePolicy;

function nodeBinding(
  root: string,
  runData: NonNullable<GraphNodeBinding['runData']>,
): GraphNodeBinding {
  return {
    prompt: null,
    scratchDirectory: root,
    workspace: { mode: 'none', directory: null, allowedPaths: [] },
    trustedCaller: {},
    permissions: [],
    policy: {
      inputBytes: 10_000,
      outputBytes: 10_000,
      timeoutMs: 5_000,
      teardownGraceMs: 100,
      memoryBytes: 10_000_000,
      filesChanged: 0,
      linesChanged: 0,
      callTokens: null,
    },
    resultContract: null,
    runData,
    parseResult: null,
    tokenBudget: null,
    decideAction: async () => ({ kind: 'allow' }),
  };
}

const temporaryRoot = await realpath(await mkdtemp(join(tmpdir(), 'obversa-pipeline-')));
const order: string[] = [];
try {
  const storage = createLocalRunStorage({
    directory: join(temporaryRoot, 'storage'),
    namespace: 'pipeline-example',
    policy: storagePolicy,
  });
  await persistRunDefinition(storage, {
    runId: 'release-pipeline-run',
    eventId: 'release-pipeline-started',
    timestamp: '2026-01-01T00:00:00.000Z',
    graphDefinition: graph.definition,
    resolvedPlan: plan,
    resolvedInputs: {},
    workspaceBinding: null,
    hostBinding: null,
  });

  const executor = await createGraphExecutor({
    runId: 'release-pipeline-run',
    graph,
    storage,
    nodes: {
      draft: nodeBinding(temporaryRoot, async () => {
        order.push('draft');
        return { article: 'ready' };
      }),
      review: nodeBinding(temporaryRoot, async ({ input }) => {
        order.push('review');
        const draft = (input as {
          readonly results: { readonly draft: { readonly article: string } };
        }).results.draft;
        return { approved: draft.article === 'ready' };
      }),
      publish: nodeBinding(temporaryRoot, async ({ input }) => {
        order.push('publish');
        const review = (input as {
          readonly results: { readonly review: { readonly approved: boolean } };
        }).results.review;
        return { published: review.approved };
      }),
    },
    engines: [],
  });
  const result = await executor.run(new AbortController().signal);
  const storedEvents = [];
  for await (const event of storage.eventStore.read({
    namespace: storage.record.namespace,
    streamId: 'release-pipeline-run',
  })) storedEvents.push(event);

  console.log(JSON.stringify({
    executor: result.kind,
    output: result.kind === 'complete' ? result.output : null,
    dispatches: storedEvents.filter(
      (event) => event.type === 'graph:node-dispatched',
    ).length,
    order,
    planDigest: plan.digest,
    bounds: plan.plan.bounds,
  }, null, 2));
} finally {
  await rm(temporaryRoot, { recursive: true, force: true });
}
```

## Exports by what you do with them

**Define the work**

- `dag`, `pipeline`, `sequence`, `parallel`, `loop`: the shapes a workflow
  takes; each returns a job you can run or nest.
- `fnJob`, `agentJob`, `defineAgent`, `defineAgentFromMarkdown`: the steps,
  from a plain function to a named agent with a brief. A `fnJob` function
  returns a full outcome, a one-line summary (a pass) or nothing (a pass
  with the label as its summary); a throw is a fail carrying the error.
  `FnJobResult` names what it may return.
  `recordAs: { role, stage }` on `agentJob` tags the answers it records with
  the seat's role and stage, so a review gate compares recorded seats
  rather than paths. A job the workflow does not build as a writer or a
  reviewer carries no tag and stands outside that gate.
- `jobMeta`, `copyJobMeta`, `renderPlan`: inspect a job's described shape,
  carry that shape onto a wrapper that keeps the job's behaviour, and render
  the plan for a reader or host.
- `commandJob`: a command as a step, pass on exit 0 and fail with the output
  as the evidence otherwise; `target` names the step that owns the fix.
- `commandSucceeds`: a condition met when a command exits 0; a launch failure
  leaves the condition unmet.
- `gateJob`: turn a condition into a job that passes when it is met and fails
  with its evidence otherwise.
- `fromFile`: read a markdown file as text for an agent's system message or
  skill instructions.
- `passed`, `failed`: conditions for a node's `when` that read a named
  dependency's outcome, so a command's exit code chooses the branch. The
  node `failed` decides on must be `optional: true`, or its red result
  would block the branch before the condition is read; `dag` refuses the
  graph otherwise and says which node to mark.
- `agentCheck`: a condition that asks an engine for a scored check before the
  graph continues; its confidence and evidence stay in the decision record.
- `isolated`: run a step in its own worktree and branch.

**Review inside it**

- `reviewPanel`, `quorum`, `tournament`: several reviewers or several
  candidates, with the threshold you set.
- `kickback`, `revisionRequest`: a reviewer sends the work back to a named
  stage with its findings.
- `RECORDED_ENGINE_USAGE`, `RecordedEngineUsage`: the state key under which a
  run records which model family answered each engine call an agent job made,
  beside the job path that made the call. When the job was built with
  `recordAs`, the entry also carries the seat's role (`writer` or `reviewer`)
  and stage. The declarative review gate reads those tags and compares the
  families that answered as writers with those that answered as reviewers.

**Run it**

- `run`: run a job from a fresh record. `callbacks` is the client the run's
  questions go through, in memory or stored (`RunCallbacks` names either);
  every job sees it as `ctx.callbacks`. `resume: true` reads the record at
  `recordTo` first. For a job built with `workflow()` it carries on from that
  record: finished stages are not repeated, a waiting gate is observed rather
  than asked again, and an interrupted stage runs again only when it carries
  `retrySafe: true`. Any other job appends to that record and runs again.
  `onCallback: 'wait'` keeps the process up until an answer arrives, instead
  of exiting with the recorded pause. The default, `'exit'`, records the
  question and returns, so a schedule can start the same file again until
  the answer is there. The question, the client and the record are the same
  in both, so a record written by one mode resumes under the other.
  Cancelling a waiting workflow reports the run as aborted and leaves the question in the record, so a later resume can still answer it. A bare `approval()` job returns the recorded pause instead.
- `LoopEvent`: the data handed to `onEvent`. Every run that begins emits one root
  `run:start` before it dispatches work and one root `run:end` before it
  returns. The end event carries the same `Outcome` and `UsageTotals` as
  `RunResult`; both events carry the run id and record path when present.
- `monitor: true` on `run` (on by default under `supervise`) serves the
  run's own page on a free loopback port; `RunResult.monitor` carries its
  address and closes it, and `MonitorState` is what `/state` returns. See
  [watch a run in the browser](/driving/monitor).
- `compileGraph`, `dagGraphType`, `createGraphExecutor`, `resolveGraphPlan`,
  `persistRunDefinition`: the graph layer, for hosts and for shapes of your
  own.
- `readRunPreflight`, `interruptRunPreflight`: read a stored run's engine
  checks without calling an engine, and close a check the process died in
  the middle of; `validateDomainEventId` checks an event id before you pass
  it to a resume. Their types: `RunPreflightPolicy`, `RunPreflightState`,
  `PreflightPauseResult`, `PreflightFailureResult`, and `GraphExecutorResult`
  for what the executor returns.

- `RESUME_STAGE_OUTCOMES`: the state key under which a resumed run carries the outcomes its stages reached before it paused; the declarative layer reads it so a gate that was already pending is observed rather than asked a second time.

**Ask a person**

- `approval`: a person's decision as a step; a yes passes, a no goes back
  to the step that owns the fix with the note as the finding, no answer
  pauses the run. `ApprovalOptions` is what it takes and `ApprovalAnswer`
  what the person gives.
- `createCallbackGate`, `createCallbackClient`, `createStoredCallbackClient`,
  `replayCallbackClient`, `directRouter`: a question with a typed answer,
  recorded so it survives a restart.
- `createApprovalCallbackGate`, `approvalSubjectDigest`, `resolveApproval`:
  an approval bound to the exact bytes it approves.

**Keep the evidence**

- `writeProofArtifact`: one stable proof packet, addressed by its digest.
- `createAcceptedResultRecord`, `resolveAcceptedResult`,
  `acceptedResultMatches`: a result bound to the inputs, proof, graph and
  workspace it was judged on.

**Choose engines, memory and workspace**

- `withEnv`, the engine and memory contracts, and the workspace provider:
  the runtime imports no adapter; your program supplies the instances.

**Test**

- `@obversa/runtime/testing`: graph definition helpers and mock engines,
  so a workflow runs offline in a test.
- `@obversa/runtime/storage/local`: `createLocalRunStorage`, the on-disk
  event and artifact stores the examples use.

## Things that catch people out

- **`run` starts a fresh record unless you pass `resume: true`.** With
  `resume`, the file at `recordTo` is read first. A job built with
  `workflow()` skips its finished stages; any other job appends to the
  record and runs again. For a workflow,
  the record applies to the same name, workspace, brief, stage list and role
  seats; change any of them and the run starts again.
  The supervised runner in `@obversa/runner` restarts a
  killed run from a graph definition and a host module.
- **Every attempt has a budget.** An overrun comes back as a typed result,
  not a hang; read the outcome rather than waiting on it.
- **The runtime imports no engine.** Nothing runs until your program hands
  it one; the examples use a mock so they run offline.

## Declare roles and stages

Write the team as one file that reads top to bottom: the brief, the
roles, the stages in order. Each stage says who does it, what it writes,
who reads it and where the work goes back to. The package compiles that
into the runtime's graph, so a review that fails sends the work back, a
command decides on its exit code, a person's answer is waited for, and
every step is on the record.

Run the same workflow again with `resume: true` and it reads its record first.
Stages that finished are skipped. A review that sent work back runs the
writer again. A gate that was still waiting for a person is observed, and the
run exits with the recorded pause, so a schedule can start the same file
until the answer arrives and never asks twice.
The record applies to the same workflow name, workspace, brief, stage list
and role seats; change the brief, or the model behind a role, and the run
starts again.
A stage that was mid-flight when the process died runs again
only when it carries `retrySafe: true`; otherwise the run pauses and asks a
person to reconcile it.

```bash
npm install @obversa/runtime @obversa/engine-claude-cli @obversa/engine-codex-cli
```

### The smallest team

A Claude seat writes the files the brief names, Node runs the test, and a
Codex seat reads the result. A rejection sends the work back to the writer.

```ts
import { claude } from '@obversa/engine-claude-cli';
import { codex } from '@obversa/engine-codex-cli';
import { run } from '@obversa/runtime';
import { briefFromFile, stage, workflow, type TeamSeat } from '@obversa/runtime';

interface WriterReviewerEngines {
  readonly claude: (model: string) => TeamSeat;
  readonly codex: (model: string) => TeamSeat;
}

const realEngines: WriterReviewerEngines = { claude, codex };

function createWriterReviewerPair(engines: WriterReviewerEngines = realEngines) {
  return workflow('writer-reviewer-pair', {
    brief: briefFromFile('briefs/add.md'),
    options: { timeout: '10m' },

    roles: {
      write: engines.claude('claude-sonnet-4-5'),
      review: [engines.codex('gpt-5.6-luna')],
    },

    stages: [
      stage('write', {
        agent: 'write',
        writes: ['src/add.mjs', 'test/add.test.mjs'],
        desc: 'Write the function and its test from the brief.',
        gate: 'The files named in the brief exist in the workspace.',
        retry: 1,
      }),
      stage('test', {
        run: ['node', '--test', 'test/add.test.mjs'],
        desc: 'Run the test command against the written files.',
        gate: 'The test command exits 0.',
        sendsBackTo: 'write',
      }),
      stage('review', {
        panel: 'review',
        agree: 1,
        desc: 'Read the code, the test and its result.',
        gate: 'The change meets the brief.',
        sendsBackTo: 'write',
      }),
    ],
  });
}

const result = await run(createWriterReviewerPair());
console.log(JSON.stringify(result.outcome, null, 2));
```

A real run of this file, and the files it left behind, are on the
[writer and reviewer](/workflows/writer-and-reviewer) page. The
[review panel](/workflows/review-panel) and
[feature delivery](/workflows/feature-team) pages do the same for the two
larger teams.

### What you get

- **`workflow(name, { brief, roles, stages, options?, post? })`.** The
  team, as a job for `run`. Stages run in the order written, each after
  the one before it.
- **`stage(name, { ... })`.** One step. Exactly one of `agent`, `run`,
  `panel` or `input` says what kind of step it is; the other keys say what
  it writes, who reads it and where the work goes back to.
- **Seats from the engine plugins.** `claude('claude-sonnet-4-5')` from
  `@obversa/engine-claude-cli`, `codex('gpt-5.6-luna')` from
  `@obversa/engine-codex-cli`, `opencode(model, { executable })` from
  `@obversa/engine-opencode-cli`. Each carries the identity the plugin
  records and starts the engine able to write files.
- **`person(question)`.** A role a person fills: the stage that names it
  puts the question to a person and waits for the answer.
- **`briefFromFile(path)`.** A brief kept as a markdown file beside the code.
  Its body is the brief; front matter may carry `files`, the paths the
  brief expects written.
- **`formatEvent(event, totals?)`.** One event of a run, as the line a person
  reads. `run` hands every event to `onEvent` as data; pass it through this to
  watch a run narrate itself without writing a formatter first. Give it the
  running totals you already hold, from `RunResult.usage` or the monitor's
  `/state`, and a usage line also reports what the run has spent so far.
  (`RunResult.stats` is a different shape: a per-model breakdown whose fields
  are named `totalInputTokens` and the rest, which this does not take.)
  Omitting them changes nothing about what it prints. The shape is
  `UsageTotals`: input and output tokens, and optionally what was created in
  and read from cache.
- **`RunResult.usage`.** What the whole run spent, in the shape
  `formatEvent` takes, so a run's own totals can be handed straight back to
  the line formatter. The same numbers are in `RunResult.stats` per model;
  this is the summary a person reads.
- **Ready-made recipes** live in [builtin-workflows](/packages/builtin-workflows):
  `writerReviewerPair`, `thresholdPanel` and `featureDelivery`.
- **`outcomeFromAgentText` from `@obversa/runtime/workflow-support`.**
  The parser the teams use on a reviewer's
  reply: the first JSON decision object becomes a pass, or a revise with
  its findings aimed at the step you name.
- **Workflow support helpers for recipe packages** from
  `@obversa/runtime/workflow-support`: `seatIdentity`,
  `assertDistinctSeats`, `requireNonEmptyFiles`, `requireNoFiles`,
  `teamAgent`, `panelReviewers`, `INVALID_TEAM_DECISION`, and
  `outcomeFromAgentText`. The subpath also exports the `ReviewerSeat`,
  `TeamInput`, and `TestCommand` types. Import `dag` from the runtime root.

### The keys of a stage

| key | what it means |
| --- | --- |
| `agent` | The role that does the work. The stage must say what it `writes`. |
| `run` | A command, one string with no quoting or an array. Exit 0 passes; a red run goes back to `sendsBackTo` with the output as the finding. It may change the files it `writes` and no other declared file; a change to another declared file fails the stage by name. Files nobody declared are not watched. |
| `panel` | A role that is a list of seats. `agree` is how many must accept; the default is all of them. |
| `input` | A person role. The stage asks the question and waits. |
| `writes` | The files this stage writes, relative to the workspace. It writes those and no other declared file. For an agent stage a missing or empty one fails the stage by name; a command stage is judged by its exit code. |
| `desc`, `gate` | What the stage does and what must be true for it to count. Both reach the reviewers and the record. |
| `reviewedBy` | A panel role that reads this stage's work. A rejection runs the stage again with the findings; a note written back unchanged fails plainly. The stage and its review are one step, so a run that dies part-way through the review runs the whole step again. It does not resume inside the review. |
| `sendsBackTo` | The earlier stage a rejection or a red run goes back to. A stage cannot send back to itself; use `reviewedBy`. |
| `retry` | How many times this stage may run again: the review restarts of a reviewed stage, or the kickback budget of a stage others send back to. Default 1. It belongs to the stage that repeats. |
| `retrySafe` | `true` when the stage may run again after an interruption without a person reconciling it. Off unless set. |
| `when` | A condition read before the stage runs: `passed(name)`, `failed(name)`, or an async predicate over `ctx`. A stage whose `when` is not met is recorded as skipped and counts as passed for the stages after it. |
| `optional` | A red run of this stage does not fail the workflow or block the stages after it. `failed(name)` on a later stage is allowed only when the named stage is optional; on a required stage a red run stops the workflow, so there is no other path to choose. |
| `needs` | One or more earlier stage names this stage also depends on, beside the one before it. A condition can then read a stage further back through `passed`, `failed` or `ctx.needs`. A name that is not an earlier stage is an error when the workflow is built. |

### The keys of a workflow

| key | what it means |
| --- | --- |
| `brief` | The work, as text or `briefFromFile`. Every model in the team reads it. |
| `roles` | Every seat and person, named once. Stages refer to the names. |
| `stages` | The steps, in order. Each needs the one before it. |
| `options.timeout` | A duration such as `'10m'`, applied to every stage. |
| `post.always` | Runs after the graph settles, with the record. |

The workspace is the directory the file runs in.

### Gotchas

- **It ships no command.** You import a workflow and run it from your own
  file.
- **A seat starts its engine unattended, and the two plugins differ.** A
  Codex seat runs sandboxed to the workspace with approvals off. A Claude
  seat runs with permission prompts off, which lets it run any command the
  process can, because the mode that only accepts edits blocks the commands
  a headless run needs. Both take an options object to choose otherwise.
  Run a team in a directory you are willing to let a model change.
- **A reviewer declares a different model family from the writer.** Every
  seat of a `reviewedBy` panel, and of a panel that sends work back to an
  agent stage, must report a different model family from that stage's seat,
  or the workflow is refused before any model runs. The panel also checks
  the model names recorded for tagged writer and reviewer answers, before
  and after review. Every recorded writer answer is checked, including
  retries. The recorded sides must have different families from each other
  and from the opposing declarations. An unreadable family fails the
  review. Untagged advisor and `agentCheck` answers are outside this check.
- **`reviewedBy` and `sendsBackTo` are two different returns.** The first
  runs the same stage again; the second goes back to an earlier one. A
  stage uses one or the other.


## Memory helpers

`@obversa/runtime/memory` exports `ground`, `curate` and `consolidate`,
with their input, option and result types. `ground` reads declared sources
into a bounded prompt; `curate` selects grounded sources with a supplied
function; `consolidate` writes a validated result with a supplied function.
The `Memory` port, commands and result types belong to `@obversa/api`.

### Memory example

`examples/memory.ts`, in full:

```ts
import { curate, type GroundedMemory } from '@obversa/runtime/memory';

const grounded: GroundedMemory = {
  documents: [
    {
      path: '/memories/project.md',
      text: 'Keep the public API small.',
      truncated: false,
    },
  ],
  missing: [],
  prompt: '',
};

const result = await curate(grounded, {
  intent: 'Prepare the next task.',
  decide: async () => ({
    brief: 'Use the project constraint.',
    sources: ['/memories/project.md'],
  }),
});

if (result.mode !== 'curated') throw new Error('Memory curation did not complete.');
console.log(JSON.stringify({ mode: result.mode, sources: result.sources }, null, 2));
```
