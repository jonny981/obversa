title: "@obversa/memory-markdown"
description: "@obversa/memory-markdown selects ranked passages from a local Markdown corpus for grounding."
---

`@obversa/memory-markdown` searches a directory of `.md` files with no index,
embedding service or network call. Each hit names the corpus file, the
matching passage, its line range (counted from 1) and a score. You choose which
hit paths to give to `ground`, and `curate` then fits the grounded text to the
next job.

Treat the text in a hit as untrusted. It's whatever the corpus file says, so a
file can carry instructions aimed at a model. Pass the hit's path to `ground`
instead of putting the passage text into a prompt yourself. `ground` marks the
content as untrusted before a job sees it.

## Requirements

Nothing beyond [Installation](/get-started/installation).

## Install

```bash
npm install @obversa/obversa
```

## Corpus

Create `memory-markdown-corpus/warranty.md` beside the example:

```md
# Coverage policy

The battery warranty lasts eight years.

Keep the purchase receipt with the installation record.
```

Create `memory-markdown-corpus/charging.md` beside it:

```md
# Charging

Charge the battery before it reaches ten percent.
```

Create `memory-markdown-corpus/notes with spaces.md` beside them:

```md
# Not indexed

Battery warranty battery warranty.
```

The third file matches the query, but its name can't become a `MemoryPath`, so
search skips it. The one remaining hit can go to `ground`.

## Source

```ts
import { access } from 'node:fs/promises';
import { fileURLToPath } from 'node:url';

import { openMarkdownCorpus } from '@obversa/memory-markdown';
import { agentJob, run } from '@obversa/runtime';
import { curate, ground } from '@obversa/runtime/memory';
import { MockEngine } from '@obversa/runtime/testing';

await access(fileURLToPath(new URL('./memory-markdown-corpus/notes with spaces.md', import.meta.url)));
const corpus = openMarkdownCorpus({
  directory: fileURLToPath(new URL('./memory-markdown-corpus', import.meta.url)),
});
const hits = await corpus.search('warranty');
const paths = [...new Set(hits.map((hit) => hit.path))];
const grounded = await ground(corpus.memory, {
  sources: paths.map((path) => ({ path })),
});

if (!grounded.ok) throw new Error(grounded.error.message);
if (paths.length !== 1 || paths[0] !== '/memories/warranty.md') {
  throw new Error('Search returned a corpus path that ground must not receive.');
}

const context = await curate(grounded.value, {
  intent: 'Answer the warranty question.',
  decide: ({ documents }) => ({
    brief: documents
      .flatMap((document) => document.text.split('\n'))
      .find((line) => line.includes('lasts')) ?? '',
    sources: documents.map((document) => document.path),
  }),
});

if (context.mode !== 'curated') throw new Error('The local curator did not return a brief.');

let receivedPrompt = '';
const engine = new MockEngine((request) => {
  receivedPrompt = request.prompt;
  return 'The warranty answer is ready.';
});
const result = await run(agentJob({
  label: 'answer-from-corpus',
  engine: 'offline',
  prompt: `Use this brief to answer the question:\n\n${context.brief}`,
}), {
  engine: 'offline',
  engines: { offline: engine },
});

console.log(JSON.stringify({
  hits: hits.map((hit) => ({
    path: hit.path,
    startLine: hit.passage.startLine,
    endLine: hit.passage.endLine,
  })),
  grounded: grounded.value.documents.map((document) => document.path),
  brief: context.brief,
  job: result.outcome.status,
  briefReachedJob: receivedPrompt.includes(context.brief),
}, null, 2));
```

The file uses the deterministic `MockEngine`, so it runs offline. Search finds
`warranty` in one file, and only that file's path reaches `ground`. `curate`
returns a short brief, and a real `agentJob` receives it.

## Read-only Memory view

The corpus exposes `corpus.memory` because `ground` reads through the public
`Memory` contract. This view is **read-only**. `view` reads the `.md` files,
and all five write commands return an error. Search must never edit the
material it selects from, and the writable adapters don't read a plain
directory of files.

Search and the Memory view include only directories and `.md` files whose
names follow one rule. Each path segment starts with a letter or number, then
uses letters, numbers, dots, underscores or hyphens. A segment can be up to
128 characters long. Dot-prefixed names, names outside that rule,
non-Markdown files and symbolic links inside the corpus are skipped without
failing the search or a directory view.

One case isn't skipped. A file whose full path is longer than 1024 bytes stops
the search, and the error names that path. A directory view still lists the
file, and that over-long path then makes `ground` refuse the whole directory.
Keep the corpus shallow enough to stay under the limit.

The corpus root itself can be a symbolic link. A corpus path such as
`policies/warranty.md` becomes `/memories/policies/warranty.md`.

## Ranking

Search splits each file at headings and paragraph breaks. A passage with the
exact phrase ranks above one that has the query terms apart. More matched terms
and more occurrences rank next. Path, then starting line, breaks ties. An empty
query, or one with no matching passage, returns `[]`.
