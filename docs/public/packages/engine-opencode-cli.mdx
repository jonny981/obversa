---
title: "OpenCode CLI Engine"
description: "@obversa/engine-opencode-cli runs isolated engine attempts through a fresh OpenCode CLI process."
---

`@obversa/engine-opencode-cli` is an engine plugin that runs one isolated engine attempt through the `opencode` command-line tool. It sets the attempt's tools and permissions, and reads back its result.

## Requirements

- OpenCode CLI 1.18.23
- Any credentials your model's provider needs, passed in the `auth` or `environment` option

## Install

```bash
npm install @obversa/obversa
```

## Identity

The plugin reports the provider and model family of the model each request
names. It reads them from the `provider/model` string with
[`modelIdentity`](/packages/api), so `anthropic/claude-sonnet-4-5` is reported
as provider `anthropic` and model family `claude`. The `identity` you pass to
the constructor is a claim about what the instance serves. A request whose
model disagrees with it is refused before anything runs.

## Usage

```ts
import { OpenCodeCliEngine } from '@obversa/engine-opencode-cli';

const engine = new OpenCodeCliEngine({
  executable: '/absolute/path/to/opencode',
  version: '1.18.23',
  identity: { provider: 'anthropic', modelFamily: 'claude' },
});
```

## Limits

- `executable` must be an absolute path.
- The plugin refuses to run any OpenCode version other than `1.18.23`.
- Structured results depend on the model following an instruction the plugin
  adds: start the final answer with the line `OBVERSA_STRUCTURED_RESULT_V1`,
  then one JSON value.
- The plugin refuses to run while a managed OpenCode config file exists in the
  system config locations. `managedConfigDirectories` adds more directories to
  that check.
