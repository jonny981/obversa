`@obversa/builtin-workflows` ships three teams you configure instead of
write: a writer and a reviewer, a review panel with a threshold, and a
nine-stage feature delivery. Give one its brief, workspace, expected files,
test command and engine seats, and it returns a job for `run` from
`@obversa/runtime`. To declare your own roles and stages, use `workflow()`
from the [Runtime](/packages/runtime#declare-a-team) instead; this package
doesn't export the builders.

The package also ships `improveWorkflow`. It reads the record of a
workflow's run, proposes one change to the workflow file, and applies it
when a person says yes. [Workflows That Improve
Themselves](/patterns/workflows-that-improve-themselves) shows it end to
end.

## Install

<CodeGroup>



## Quickstart

A writer, a real Node check and a reviewer, with scripted engines so it
runs offline:

```ts examples/builtin-workflows.ts (excerpt) {1,5-6,7-11}
  const job = writerReviewerPair({
    brief: 'Write answer.txt containing 42 followed by a newline.',
    workspace,
    files: ['answer.txt'],
    writer,
    reviewer,
    test: {
      command: process.execPath,
      args: ['-e', 'require("node:assert/strict").equal(require("node:fs").readFileSync("answer.txt", "utf8"), "42\\n")'],
      timeoutMs: 5_000,
    },
  });
  const result = await run(job, { recordTo: join(workspace, 'run.jsonl') });
```

The writer writes the file, the test command checks it, and the reviewer
reads it back; a rejection returns the findings to the writer. Run it with
`npx tsx builtin-workflows.ts`:

```json Output
{
  "status": "pass",
  "writes": 1,
  "reviews": 1
}
```

## Choose a recipe

| Function | What it runs | Configuration |
| --- | --- | --- |
| `writerReviewerPair` | A writer, the test command, and a reviewer whose findings return to the writer. | `PairConfig`: `writer`, `reviewer`, optional `refine`. |
| `thresholdPanel` | An implementation, the test command, and a panel that needs `threshold` acceptances. | `PanelConfig`: `implement`, `reviewers`, `threshold`, optional `refine`. |
| `featureDelivery` | A seat check, a brief check, the build, the builder's report, a size check, the checks, a proof check and the review panel, with an optional commit. Research, planning and tests run first when their seats are given. | `FeatureDeliveryConfig`: see [Feature delivery](#feature-delivery). |

`writerReviewerPair` and `thresholdPanel` take a `TeamInput`. A seat is a `TeamSeat` from
`@obversa/api`, an engine with its declared identity:

```ts examples/builtin-workflows.ts (excerpt) {1-2,7-10}
  const writer: TeamSeat = {
    engine: new MockEngine(() => {
      writes += 1;
      writeFileSync(answer, '42\n');
      return JSON.stringify({ status: 'pass', summary: 'Wrote the answer.' });
    }),
    identity: {
      adapter: 'mock', provider: 'local', modelFamily: 'writer',
      model: 'writer-offline', tools: ['Write'],
    },
  };
```

## Feature delivery

`featureDelivery(config)` builds one change in a worktree and runs it to a
passed, reviewed change. It runs these steps in order:

1. **Seat check.** Each seat whose engine has an admission check starts its
   CLI and reports its version, before any build spend. A seat that cannot
   start is replaced by its next candidate, and every later step starts on
   the seat that answered. With no candidate left, the run pauses and names
   the seat.
2. **Brief check.** The first reviewer reads the brief against the
   repository and lists every finding it can establish, in one pass. With
   `houseRules`, it reads the house rules too. It blocks only on a wrong
   goal, a false claim about the repository or its base, a check that
   cannot fail, or a house rule that says the brief check blocks it. It
   never blocks because the tree does not yet do what the brief asks the
   build to do. A block pauses the run. With `briefPath`, a resume reads
   the brief file again, so a fixed brief needs no relaunch. A warning
   goes to the builder.
3. **Build.** The `implement` seat builds the change. Its report ends with a
   commit message in a fenced block marked `commit`.
4. **Report.** The builder's report goes to the team.
5. **Size check.** The review input is measured for every reviewer seat. A
   change too large for one, even with data files listed, goes back to the
   build with its largest files named, before any check runs.
6. **Checks.** Each command in `checks` runs on the tree. A failure runs
   once more before it counts. A failure's output goes to the builder once,
   cut to fit the builder's whole next prompt.
7. **Proof check.** The `reader` (the first reviewer by default) asks only
   for proof the run cannot produce itself. A check the run passed counts
   as proven. The first missing-proof send-back in a run goes to the report
   and costs no review round; a later one goes to the build, with the report
   the proof check read. A resumed run keeps both.
8. **Review.** The panel reviews the change, with the judge between its
   verdict and each send-back. From round 2 each reviewer reads its own open
   findings and the diff since its last round.

Only the review panel's verdicts go through the judge. A failed check, a
change too large to review and missing proof go straight back to their
step, so a judge never passes a tree whose checks failed.

The report's answer to a send-back runs on the builder's seat and its
candidates, as the build does.

With `commit: true`, a passed run commits its work with the report's
commit message. See [`commit`](/packages/runtime#commit).

### Accepted proofs

Each proof the proof check accepts is kept with the brief item it answers,
the tree it was accepted on and the files it covers. The proof check names
those files: the code the proof tests or measures, its test file and the
script it ran. A proof with no files named covers the whole change. A later
report replaces the last report, but never the accepted list, and a resumed
run reads the list back from the record. The run's own files (its record,
the records kept beside it and its check output) are never part of a
proof's tree, so a record inside the worktree does not stale a proof. A
proof stands until the diff from
its tree to the current tree touches a file it covers. The builder's prompt
lists the proofs that stand, so it does not run them again.

### Carrying on from an earlier run

Run it with `run`'s [`carryFrom`](/packages/runtime#carryfrom) to carry on
from an earlier run on the same brief. The first build answers the earlier
run's open findings, and its accepted proofs still stand while their files
are unchanged. The first build and the brief check are both told that the
worktree may hold the earlier run's work, and how that run ended, so the
brief needs no note about it.

## Improve a workflow

`climbWorkflow(config)` scores a proposed change to a workflow file. It runs
the workflow on tuning tasks and held-out tasks, with and without the
change, and keeps the change only when the workflow scores better with it.
A person approves a kept change. With `mode: 'auto'`, the numbers alone
decide for a change that the `auto` option allows: the files, and the
settings keys and values, it may change. Any other kept change goes to a
person. `formatClimbReport(report)` prints the comparison. See
[Workflows that improve themselves](/reviewing/workflows-that-improve-themselves).

## Read a review decision

`outcomeFromAgentText(text, target?)` reads a reviewer's reply: the first
JSON decision object becomes a pass, or findings aimed at `target`.
`INVALID_TEAM_DECISION` is the message for a reply that holds no decision.
Both are re-exported from `@obversa/runtime/workflow-support`.

## Options

### `TeamInput`

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `brief` | `string` | required | The work, as every seat reads it. |
| `workspace` | `string` | required | The directory the team writes in. |
| `files` | `readonly string[]` | required | The files the brief expects written. |
| `test` | `TestCommand` | required | `{ command, args, timeoutMs? }`, run after the writer. |
| `houseRules` | `string` | none | Rules every seat reads. |

### `FeatureDeliveryConfig`

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `brief`, `briefPath` | `string` | one required | The brief as text, or as a file read again on a resume. |
| `workspace` | `string` | required | The worktree the team builds in. |
| `implement` | `SeatChoice` | required | The seat that builds, with its candidates. |
| `reviewers` | `readonly ReviewerSeat[]` | required | The panel. The first also checks the brief. |
| `reviewThreshold` | `number` | all reviewers | How many reviewers must pass a round. |
| `reader` | `SeatChoice` | the first reviewer | The seat that checks the report's proof. |
| `judge` | `TeamSeat` | none | The judge between each review and its send-back. |
| `cap` | `number` | none | The judge's cap on rounds. |
| `rounds` | `number` | `3` | The send-backs the build takes when there is no judge. |
| `checks` | `readonly (string \| readonly string[])[]` | required | The commands the change must pass, with no shell syntax. |
| `base` | `string` | `'origin/main'` | What the change is measured against. |
| `buildMinutes` | `number` | `120` | Minutes one build attempt may run. |
| `reviewMinutes` | `number` | `40` | Minutes the brief check, the proof check and each reviewer may run. |
| `stallMinutes` | `number` | none | Minutes with no engine event before a step counts as stalled. |
| `commit` | `boolean` | `false` | Commit the work when the run passes. |
| `houseRules` | `string` | none | Rules every seat reads. |
| `analyse` | `SeatChoice` | none | With it, the research and plan stages run before the build. |
| `files` | `readonly string[]` | required with `analyse` or `testFiles` | The files the change writes. |
| `testFiles` | `readonly string[]` | none | With them, the tests stage runs before the build; every entry must be in `files`. |
| `refine` | `RefineBudget` | `1` | The send-backs the research, plan and tests stages take. |

### Seats and thresholds

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `writer`, `reviewer`, `implement` | `TeamSeat` | required | One engine with its identity per role. |
| `reviewers` | `readonly ReviewerSeat[]` | required | Each a `name`, a `seat` and an optional review `scope`. |
| `threshold` | `number` | required | How many reviewers must accept. |
| `refine` | `RefineBudget` | `1` | The send-backs each target may take. A number gives every target the same count. A map gives each named target its own count or judge, and a target the map leaves out refuses send-backs. |

## Errors

- **A reply with no decision** is marked `INVALID_TEAM_DECISION` by
  `outcomeFromAgentText`.
- **Seats from one model family** on both sides of a review are refused
  before any model runs.

<Accordion title="Full file">

```ts examples/builtin-workflows.ts
import assert from 'node:assert/strict';
import { readFileSync, writeFileSync } from 'node:fs';
import { mkdtemp, realpath, rm } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { join } from 'node:path';

import type { TeamSeat } from '@obversa/api';
import { writerReviewerPair } from '@obversa/builtin-workflows';
import { MockEngine } from '@obversa/core/testing';
import { run } from '@obversa/runtime';

const workspace = await realpath(await mkdtemp(join(tmpdir(), 'obversa-pair-')));
const answer = join(workspace, 'answer.txt');
let writes = 0;
let reviews = 0;

try {
  const writer: TeamSeat = {
    engine: new MockEngine(() => {
      writes += 1;
      writeFileSync(answer, '42\n');
      return JSON.stringify({ status: 'pass', summary: 'Wrote the answer.' });
    }),
    identity: {
      adapter: 'mock', provider: 'local', modelFamily: 'writer',
      model: 'writer-offline', tools: ['Write'],
    },
  };
  const reviewer: TeamSeat = {
    engine: new MockEngine(() => {
      reviews += 1;
      assert.equal(readFileSync(answer, 'utf8'), '42\n');
      return JSON.stringify({ status: 'pass', summary: 'The answer matches the brief.' });
    }),
    identity: {
      adapter: 'mock', provider: 'local', modelFamily: 'reviewer',
      model: 'reviewer-offline', tools: ['Read'],
    },
  };
  const job = writerReviewerPair({
    brief: 'Write answer.txt containing 42 followed by a newline.',
    workspace,
    files: ['answer.txt'],
    writer,
    reviewer,
    test: {
      command: process.execPath,
      args: ['-e', 'require("node:assert/strict").equal(require("node:fs").readFileSync("answer.txt", "utf8"), "42\\n")'],
      timeoutMs: 5_000,
    },
  });
  const result = await run(job, { recordTo: join(workspace, 'run.jsonl') });
  assert.equal(result.outcome.status, 'pass');
  assert.equal(writes, 1);
  assert.equal(reviews, 1);
  console.log(JSON.stringify({ status: result.outcome.status, writes, reviews }, null, 2));
} finally {
  await rm(workspace, { recursive: true, force: true });
}
```

</Accordion>

## API

- **`writerReviewerPair(config)`**, **`thresholdPanel(config)`**,
  **`featureDelivery(config)`**: the three recipes.
  [Choose a recipe](#choose-a-recipe).
- **`improveWorkflow(config)`**: one change to a workflow file from its
  run's record, applied on a person's yes. `ImproveWorkflowConfig` takes
  `record`, `workflow`, `proposer` and `reviewer`.
  [Workflows That Improve Themselves](/patterns/workflows-that-improve-themselves).
- **`climbWorkflow(config)`**, **`formatClimbReport(report)`**: keep a
  change to a workflow only when it scores better.
  [Improve a workflow](#improve-a-workflow).
- **`outcomeFromAgentText`**, **`INVALID_TEAM_DECISION`**: read a
  reviewer's reply. [Read a review decision](#read-a-review-decision).
- **Types**: `PairConfig`, `PanelConfig`, `FeatureDeliveryConfig`,
  `ImproveWorkflowConfig`, `TeamInput`, `TestCommand`, `ReviewerSeat`, `ClimbAuto`, `ClimbConfig`,
  `ClimbProtection`, `ClimbReport`, `ClimbRun`, `ClimbSettingRule`,
  `ClimbTaskReport`, `ClimbTotals`.
