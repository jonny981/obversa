title: "Jev API Engine"
description: "@obversa/engine-jev-api answers decision questions over recorded run state through the Jev API."
---

`@obversa/engine-jev-api` is an engine plugin for Jev, which answers structured
questions about state your run already recorded. Use it for assessments, such
as whether to send work back, which stage should take it, or how ready a change
is to land. Each attempt makes one Jev decision call over the TypeSafe API and
returns Jev's answers as its structured result.

Jev runs with workspace mode `none`. It never reads or edits files.

## Requirements

- A Jev endpoint and API key, passed as the `endpoint` and `apiKey` options

## Install

```bash
npm install @obversa/obversa
npm install @obversa/engine-jev-api
```

`@obversa/obversa` doesn't include the Jev engine, so it's a separate install.

## Request shape

The prompt is a JSON document of the shape `{state, questions}`:

```json
{
  "state": { "diff": "..." },
  "questions": {
    "send_back": {
      "type": "noul",
      "instructions": "Should this work be sent back for more iteration?",
      "criteria": {
        "true": "A finding describes incorrect behaviour a user would see",
        "false": "The findings are cosmetic or advisory only"
      }
    },
    "which_stage": {
      "type": "choice",
      "instructions": "Which stage should the work go back to?",
      "criteria": {
        "implement": "The defect is in the code itself",
        "test": "The code is right but the tests do not prove it",
        "none": "Nothing needs to go back"
      }
    },
    "readiness": {
      "type": "score",
      "instructions": "How ready is this change to land?",
      "criteria": ["Unsafe to land", "Needs another round", "Lands clean"]
    }
  }
}
```

`state` is whatever your run recorded. Each entry in `questions` names a type
(`noul`, `choice` or `score`), with instructions and criteria. For a `noul`
(true or false) question, the criteria say what true and false mean. For
`choice`, they map each option to its description. For `score`, they're the
array of labels the score indexes.

The adapter returns the answer objects unchanged and doesn't check their
shape. What follows is what the provider has been seen to return, not a type
the adapter guarantees. A `noul` answer carries a probability and no separate
`confidence` field. `choice` and `score` answers carry a `confidence`, and may
carry `probabilities`.

Before any network call, the adapter checks that the prompt parses to an
object, that `questions` is a non-empty object, and that every question names
one of the three types. Malformed input fails as `invalid-config`. A missing or
`null` `state` is sent as an empty object. The adapter doesn't inspect
`criteria`. It forwards them to the provider unchanged.

## Usage

```ts
import { JevApiEngine } from '@obversa/engine-jev-api';

const apiKey = process.env.TYPESAFE_API_KEY;
if (!apiKey) {
  throw new Error('TYPESAFE_API_KEY is not set');
}

const engine = new JevApiEngine({
  endpoint: 'https://api.typesafe.ai/v1/systemone',
  apiKey,
});
```

The result's structured value is the `answers` object itself, so a binding's
`parseResult` reads `part.value.send_back` directly.

## Unsupported requests

These request fields fail as `invalid-config` before any network call:

- `system` or `systemMode`: Jev requests carry no system prompt
- `env`: the key comes from the `apiKey` option, not the request
- `maxTokens`: Jev has no server-side token cap
- a `workspaceMode` other than `none`
- a non-empty `tools` list: the adapter declares no tools

## Limits

- One HTTP request per attempt. The adapter never retries by itself. Retry
  safety belongs to the node's binding.
- Provider response data, including error bodies, is recorded in the result
  and in error details.
- `timeoutMs`, plus `timeoutGraceMs` when set, bounds the whole call, from
  connecting to reading the response body. Past that deadline the call fails
  as `timeout`. A caller abort fails as `aborted`.
- `maxOutputBytes`, when set on the request, caps the response body the adapter
  reads. It isn't a general memory limit.
- A low-confidence answer completes like any other result. Thresholds and
  routing are up to your workflow.
- If the API doesn't echo a model, or echoes one that can't be read, the
  recorded effective model and model family are both `null`. The answers are
  still returned.
