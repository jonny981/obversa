title: "Git Memory"
description: "@obversa/memory-git stores scoped run memory in private Git references without touching branches."
---

`@obversa/memory-git` is a memory adapter that stores key documents in private Git references. It isolates memories by scope digest under `refs/obversa/memory/v1`, without modifying the working tree, index, or active branch.

## Requirements

- Node.js 22.12 or later
- Git

## Install

```bash
pnpm add @obversa/memory-git
```

## Usage

```ts
import { openGitMemory } from '@obversa/memory-git';

const memory = await openGitMemory({
  repositoryPath: process.cwd(),
  scope: 'example-run',
});

await memory.execute({
  command: 'create',
  path: '/memories/notes.md',
  text: 'Keep the result small.\n',
});

const view = await memory.execute({
  command: 'view',
  path: '/memories/notes.md',
});
```

## The reasoning record

The same package opens a second thing over the same repository, with
different semantics. `openGitMemory` uses Git as a store: a private
reference per scope, a tree, no commits, and nothing that touches your
HEAD or your working tree. `openReasoningRecord` uses Git as the record:
what a stage was thinking while it worked, composed into the commit body
of the work itself, where it sits against the lines it explains and every
tool a reader already has can find it.

A stage opts in, and nothing is paid for where it is not chosen. The
record reads the run's own events, so a writer's turns are captured as
they happen rather than summarised afterwards, and at the stage boundary
one call composes them into a body. If that call fails or has nothing to
say, a body is still written from the outcome, so a routine iteration
leaves a trace instead of a gap.

```ts
import { openReasoningRecord } from '@obversa/memory-git';

const record = await openReasoningRecord({
  repositoryPath: workspace,
  stage: 'implement',
  compose: ({ captured, outcome }) => composeBody(captured, outcome),
});

const result = await run(job, { onEvent: (event) => record.observe(event) });
await record.close(result.outcome);
```

A stage that asks to record in a directory that is not a Git repository is
refused by name rather than having its reasoning dropped in silence.

## Commands

The adapter supports six memory operations:
- `create`: Write a new file at a path.
- `view`: Read file content, with optional line range.
- `str_replace`: Replace unique text inside a file.
- `insert`: Insert text at a zero-based line index.
- `delete`: Remove a file from memory.
- `rename`: Move a file to a new path within the memory root.

## Limits

- Default limits: 64 KB per file, 1 MB total memory per scope, and at most 256 files.
- Allowed file extensions: `.txt`, `.md`, `.json`, `.py`, `.yaml`, `.yml`.
- Paths must be relative to the memory root `/memories/` and cannot escape root boundaries.
