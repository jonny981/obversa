title: "Git Memory"
description: "@obversa/memory-git keeps scoped run memory in private Git references, and writes a stage's reasoning into the commit that carries its change."
---

`@obversa/memory-git` uses Git in two ways: as a store and as a record. `openGitMemory` is a memory adapter that keeps memory files in private Git references, with no commits. Each scope gets its own reference under `refs/obversa/memory/v1`, named by a digest of the scope. The adapter never touches your working tree, index or current branch. `openReasoningRecord` writes why a stage made a change into the body of the commit that carries it.

## Requirements

- Git

## Install

```bash
npm install @obversa/obversa
```

## Usage

```ts
import { openGitMemory } from '@obversa/memory-git';

const memory = await openGitMemory({
  repositoryPath: process.cwd(),
  scope: 'example-run',
});

await memory.execute({
  command: 'create',
  path: '/memories/notes.md',
  text: 'Keep the result small.\n',
});

const view = await memory.execute({
  command: 'view',
  path: '/memories/notes.md',
});
```

## The reasoning record

`openReasoningRecord` makes no commit of its own. A stage that opts in already
runs in its own worktree, and its work is committed there before it merges
back. The reasoning belongs on that commit. A second commit would be a note
beside the work, and a note isn't attached to any line. So the record watches
the stage work and, when there's something to commit, supplies that commit's
message.

The record captures the stage's words while it works. A summary written
afterwards has already lost the discarded attempts, and those are the part a
later reader can't reconstruct. If `compose` throws or returns nothing usable,
the record builds the message from the stage's outcome instead, so a change
never lands with a body that explains nothing.

```ts
import { openReasoningRecord } from '@obversa/memory-git';
import { isolated, run } from '@obversa/runtime';

const record = openReasoningRecord({
  stage: 'implement',
  compose: ({ captured, outcome }) => ({
    subject: `feat(implement): ${outcome.summary ?? 'the change'}`,
    body: ['## Why', '', ...captured.map((turn) => turn.text)].join('\n'),
  }),
});

await run(isolated(implement, { label: 'implement', record }), {
  onEvent: (event) => record.observe(event),
});
```

The `stage` option names the stage. The record waits for the first turn whose
path carries that name, and binds to the path up to that name. From then on it
takes only turns under that path. A sibling running beside it is left out, and
so is a stage of the same name elsewhere in the run. Pass `path` to bind the
record before it sees anything.

A stage that changed nothing makes no commit, so it gets no body.

Opting in takes two steps: pass the record to the stage, and pass the run's
events to `record.observe`. `examples/reasoning-record.ts` does both against a
real repository, then reads the reasoning back from the commit that carries
the change.

## Commands

`openGitMemory` supports all six commands of the [memory port](/memory):
- `create`: Write a file at a path, replacing any file already there.
- `view`: Read a file, with an optional line range.
- `str_replace`: Replace unique text inside a file.
- `insert`: Insert text at a zero-based line index.
- `delete`: Remove a file from memory.
- `rename`: Move a file to a new path within the memory root.

## Limits

- Default limits: 64 KB per file, 1 MB total memory per scope, and at most 256 files.
- Allowed file extensions: `.txt`, `.md`, `.json`, `.py`, `.yaml`, `.yml`.
- Every path must be inside `/memories`.
