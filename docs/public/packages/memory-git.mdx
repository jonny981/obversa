title: "Git Memory"
description: "@obversa/memory-git stores scoped run memory in private Git references without touching branches."
---

`@obversa/memory-git` is a memory adapter that stores key documents in private Git references. It isolates memories by scope digest under `refs/obversa/memory/v1`, without modifying the working tree, index, or active branch.

## Requirements

- Node.js 22.12 or later
- Git

## Install

```bash
pnpm add @obversa/memory-git
```

## Usage

```ts
import { openGitMemory } from '@obversa/memory-git';

const memory = await openGitMemory({
  repositoryPath: process.cwd(),
  scope: 'example-run',
});

await memory.execute({
  command: 'create',
  path: '/memories/notes.md',
  text: 'Keep the result small.\n',
});

const view = await memory.execute({
  command: 'view',
  path: '/memories/notes.md',
});
```

## The reasoning record

The same package opens a second thing, and the difference between them is
where the words land. `openGitMemory` uses Git as a store: a private
reference per scope, a tree, no commits, and nothing that touches your HEAD
or your working tree. `openReasoningRecord` uses Git as the record: why a
change was made, written into the body of the commit that carries it.

It writes no commit of its own. A stage that opts in already runs in its
own worktree and is committed there before its work merges back, and that
commit is the one the reasoning belongs on; a second commit would be a note
beside the work, and a note is not attached to a line. So the record
watches the stage work and, when there is something to commit, supplies
that commit's message.

What it captures is captured while the stage works, because a summary
written afterwards has already lost the discarded attempt, which is the
part a later reader cannot reconstruct. Composition has a floor: if the
call that composes fails or returns nothing usable, the message is still
built from the outcome, so a change never lands with a body that explains
nothing.

```ts
import { openReasoningRecord } from '@obversa/memory-git';
import { isolated, run } from '@obversa/runtime';

const record = openReasoningRecord({
  stage: 'implement',
  compose: ({ captured, outcome }) => ({
    subject: `feat(implement): ${outcome.summary ?? 'the change'}`,
    body: ['## Why', '', ...captured.map((turn) => turn.text)].join('\n'),
  }),
});

await run(isolated(implement, { label: 'implement', record }), {
  onEvent: (event) => record.observe(event),
});
```

The stage names itself, so the record keeps that stage's turns and leaves a
sibling running beside it alone. Pass a `path` only when a stage's own path
in the run is not the one its name would find.

A stage that changed nothing produces no commit, so it produces no body.

## Commands

The adapter supports six memory operations:
- `create`: Write a new file at a path.
- `view`: Read file content, with optional line range.
- `str_replace`: Replace unique text inside a file.
- `insert`: Insert text at a zero-based line index.
- `delete`: Remove a file from memory.
- `rename`: Move a file to a new path within the memory root.

## Limits

- Default limits: 64 KB per file, 1 MB total memory per scope, and at most 256 files.
- Allowed file extensions: `.txt`, `.md`, `.json`, `.py`, `.yaml`, `.yml`.
- Paths must be relative to the memory root `/memories/` and cannot escape root boundaries.
